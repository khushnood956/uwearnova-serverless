# 04 — API Contract

## 1. Conventions

- Base path: `/api/v1`
- JSON REST endpoints.
- OpenAPI generated by FastAPI and kept accurate.
- Use plural resource names.
- Use consistent response/error formats.
- Paginate collection endpoints.
- Validate inputs at the API boundary and business rules in services.
- Use explicit API schemas; do not expose ORM models directly.
- Use UTC ISO-8601 timestamps.
- Use decimal-safe string or documented JSON numeric representation for money; never allow binary floating-point rounding to corrupt totals.

Suggested success response:

```json
{
  "data": {},
  "meta": {}
}
```

Suggested error response:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request could not be processed.",
    "details": []
  }
}
```

Exact envelopes may follow existing frontend conventions if already established. Avoid needless breaking changes.

## 2. Endpoint groups

### Health
- `GET /health`
- `GET /ready`

Readiness should verify critical dependencies without exposing secrets or internal configuration.

### Authentication
- `POST /auth/register` (if public registration is enabled)
- `POST /auth/login`
- `POST /auth/logout`
- `POST /auth/refresh` (only if token/session design requires it)
- `GET /auth/me`
- `POST /auth/forgot-password`
- `POST /auth/reset-password`
- `POST /auth/verify-email`

### Public catalogue
- `GET /categories`
- `GET /collections`
- `GET /products`
- `GET /products/{slug}`
- `GET /products/{slug}/related`

Support bounded search, category, size, color, price and sort filters. Validate sort fields to prevent arbitrary SQL ordering.

### Customer account
- `GET/PATCH /account/profile`
- `GET/POST/PATCH/DELETE /account/addresses`
- `GET /account/orders`
- `GET /account/orders/{order_number}`
- `GET/POST/DELETE /account/wishlist`
- `POST /account/returns`
- `GET /account/returns`

### Cart and checkout
- `GET /cart`
- `POST /cart/items`
- `PATCH /cart/items/{item_id}`
- `DELETE /cart/items/{item_id}`
- `POST /checkout/quote`
- `POST /checkout/orders`

Checkout quote returns server-calculated line items, discounts, shipping and total. Order creation must revalidate all values and use idempotency protection.

### Orders and payments
- `GET /orders/{order_number}` (ownership or staff permission required)
- `POST /orders/{order_number}/cancel` (state-policy controlled)
- `POST /payments/{payment_id}/initialize`
- `POST /webhooks/payments/{provider}`

Webhook routes must verify signatures and deduplicate provider event IDs.

### Admin/staff
- `/admin/products`
- `/admin/categories`
- `/admin/collections`
- `/admin/inventory`
- `/admin/orders`
- `/admin/customers`
- `/admin/promotions`
- `/admin/returns`
- `/admin/payments`
- `/admin/shipping`
- `/admin/staff`
- `/admin/roles`
- `/admin/reports`
- `/admin/settings`
- `/admin/audit-logs`

Use `/staff/...` only where a separate staff-facing route materially improves clarity. Authorization must remain permission-based.

## 3. Order lifecycle

Define and document an explicit state machine before implementing order updates. A starting proposal:

- `pending_confirmation`
- `confirmed`
- `processing`
- `packed`
- `shipped`
- `delivered`
- `cancelled`
- `return_requested`
- `returned`
- `refunded` (payment state may be separate)

Do not allow arbitrary status changes. Validate allowed transitions in a service and record every transition.

Keep these concepts separate:
- Order status
- Payment status
- Fulfillment/shipment status
- Return/refund status

COD orders can be confirmed and fulfilled while payment remains unpaid until collection is confirmed.

## 4. Frontend integration contract

Before replacing local data:
1. Inspect the existing frontend types and contexts.
2. Define API response schemas matching actual UI needs.
3. Add a typed API client and centralized error handling.
4. Add loading/error/empty states.
5. Preserve cart behavior during migration.
6. Migrate one domain at a time.
7. Avoid scattering raw `fetch` calls throughout components.

The API contract should be updated whenever an endpoint or response changes.
